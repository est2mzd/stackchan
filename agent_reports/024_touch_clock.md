# 画面タッチで時計に戻れない件

## 背景

ユーザが会話のあと画面を押しても時計に戻れないと報告した。以前の対策で、会話中のタッチは無視し、「時計モード」と発話したときだけ戻すようにしていた。加えて、録音中は本体がタッチをホストへ送っていなかった。

参照: `agent_reports/018_no_response.md`。

## 目的

| 完了条件 | 状態 |
| --- | --- |
| 録音中でもタッチをホストへ送る | 完了 |
| 会話中のタッチで時計に戻る | 完了 |
| 時計中のタッチで会話を始める | 完了（従来どおり） |
| ファーム書き込みとホスト再起動 | 完了 |

## 結論

戻れなかった理由は二つある。ホストが会話中の `touch` を捨てていたことと、本体が録音中（`listening`）にタッチを送っていなかったことである。会話のほとんどの時間は録音中なので、押しても何も起きなかった。

いまは、時計で押すと会話、会話で押すと時計。PCM 受信中だけタッチを遅らせる（バイナリに混ぜないため）。発話「時計モード」でも戻れる。

ファームを焼き、ホストを起動した。会話中に画面を押して日付・時刻に戻るか確認する。

```
+---------------------------+        USB         +---------------------------+
| PC                        | -----------------> | StackChan                 |
|                           |  時計 / 聞け       |                           |
|  中でやること             |                    |  中でやること             |
|    時計なら会話を始める   | <----------------- |    押したら touch を送る |
|    会話なら時計に戻す     |  touch             |    録音中も送る          |
+---------------------------+                    +---------------------------+
```

使わなかった構成（会話中はタッチ無視。戻れない）:

```
+---------------------------+        USB         +---------------------------+
| PC                        | -----------------> | StackChan                 |
|                           |  聞け              |                           |
|  中でやること             |                    |  中でやること             |
|    会話中の touch を捨てる| <----------------- |    録音中は touch を出さない|
+---------------------------+                    +---------------------------+
```

未完了: ユーザが画面で時計に戻れるかの確認（ホストは起動済み）。スピーカーのざーーーは対象外。
