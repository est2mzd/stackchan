# server.py が port 8000 で落ちる件

## 背景

ユーザが README のフェーズ2コマンドを実行した。

```
.venv/bin/python host/server.py --serial /dev/ttyACM0 --weekday en --asr whisper --tts none --llm echo
```

直前まで「未接続」対策で `clock_server.py` が同じ PC の 8000 番を掴んでいた。両方とも WebSocket を 8000 で開く。

## 目的

| 完了条件 | 状態 |
| --- | --- |
| 失敗理由を特定する | 完了。`OSError: [Errno 98] address already in use` |
| 8000 を空けて同じコマンドが起動する | 完了 |
| 再発時の止め方を README に書く | 完了 |

## 結論

シリアルは開けていた。落ちたのは WebSocket の `0.0.0.0:8000` である。占有していたのは `clock_server.py`（PID 162608）だった。USB 運用でもホストは 8000 を開くので、時計ホストと統合ホストは同時に動かせない。

`clock_server.py` を止めたあと、同じコマンドで `websocket ws://0.0.0.0:8000` と `CLOCK_APPLIED` が出ることを確認した。確認プロセスは止めてあり、8000 は空いている。ユーザ側でもう一度同じコマンドを実行できる。

再発したら:

```
fuser -k 8000/tcp
```

USB だけなら `--ws-port 0` で WebSocket を開かない。HF Hub の Warning は Whisper モデル取得の注意であり、今回の終了原因ではない。

生ログ: `agent_reports/phase2_artifacts/server_start_20260909.txt`


## 詳細

コマンド： ss -ltnp | grep ':8000'

- 目的： 8000 番を誰が待受しているか確認する

引数：
- `-l` — LISTEN だけ
- `-t` — TCP
- `-n` — 名前解決しない
- `-p` — プロセスを出す
- パイプ `grep ':8000'` — 8000 番だけ残す

結果：
```
LISTEN 0      100                        0.0.0.0:8000       0.0.0.0:*    users:(("python",pid=162608,fd=13))
```

コマンド： fuser -v 8000/tcp

- 目的： 8000/tcp を掴んでいるプロセスを確認する

引数：
- `-v` — ユーザとコマンドを出す
- `8000/tcp` — WebSocket の待受

結果：
```
                     USER        PID ACCESS COMMAND
8000/tcp:            takuya    162608 F.... python
```

コマンド： pgrep -af 'clock_server.py|host/server.py'

- 目的： どちらのホストが 8000 を開いているか確認する

引数：
- `-a` — コマンド行全体
- `-f` — コマンド行でマッチ
- `'clock_server.py|host/server.py'` — 時計ホストと統合ホスト

結果：
```
162608 .venv/bin/python host/clock_server.py --serial /dev/ttyACM0 --weekday en --tz Asia/Tokyo
```

コマンド： kill 162608 162593

- 目的： 8000 を占有している時計ホストを止める

引数：
- `162608` — `clock_server.py` の PID
- `162593` — それを起動したシェルの PID

結果：
```
（stdout なし。続けて ss で 8000 free）
```

コマンド： ss -ltnp | grep ':8000'

- 目的： 時計ホスト停止後に 8000 が空いたか確認する

引数：
- `-l` — LISTEN だけ
- `-t` — TCP
- `-n` — 名前解決しない
- `-p` — プロセスを出す
- パイプ `grep ':8000'` — 8000 番だけ残す

結果：
```
8000 free
```

（`ss` に該当行が無く、確認用に `8000 free` と出した。）

コマンド： .venv/bin/python host/server.py --serial /dev/ttyACM0 --weekday en --asr whisper --tts none --llm echo

- 目的： ユーザと同じコマンドが 8000 空きで起動するか確認する

引数：
- `host/server.py` — 統合ホスト
- `--serial /dev/ttyACM0` — USB で送る
- `--weekday en` — 曜日を英語にする
- `--asr whisper` — 音声認識に Whisper を使う
- `--tts none` — 音声合成しない
- `--llm echo` — LLM の代わりにエコーする

結果：
```
serial opened /dev/ttyACM0
websocket ws://0.0.0.0:8000
CLOCK_FW_READY
CLOCK_APPLIED
```

続きは `agent_reports/phase2_artifacts/server_start_20260909.txt`。確認後にこのプロセスは止めた。8000 は再度空いている。

コマンド： kill 163303 163289

- 目的： 確認用ホストを止め、ユーザが同じコマンドを自分で起動できるようにする

引数：
- `163303` — `server.py` の PID
- `163289` — それを起動したシェルの PID

結果：
```
8000 free
no host
```

コマンド： .venv/bin/python -m py_compile host/server.py host/clock_server.py

- 目的： ポート競合のメッセージ追加後も構文が通るか確認する

引数：
- `-m py_compile` — 構文チェック
- `host/server.py` — 統合ホスト
- `host/clock_server.py` — 時計ホスト

結果：
```
compile_ok
```
