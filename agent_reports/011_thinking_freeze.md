# 「考え中」で画面が止まる件

## 背景

会話モードで発話すると液晶が「考え中」のまま進まない。ホストは `--llm echo` なので返事自体はすぐ作れる。ログでは `asr 'こんにちは'` のあとに `reply` が出ておらず、続けてマイクの `pcm_end` と Whisper が走っていた。

## 目的

| 完了条件 | 状態 |
| --- | --- |
| echo では「考え中」を出さず返事を描く | 完了（ホスト再起動が必要） |
| 時計の 1 秒送信と会話 JSON がシリアルで混線しない | 完了（書き込みロック） |
| Whisper 中もシリアルを読み続ける | 完了 |
| ファームがマイク JSON で `loop` を塞がない | コードはビルド済み。実機への書き込みはホストがポートを掴んでいるため未実施 |

## 結論

止まり方は次の重なりである。

1. 「考え中」を出した直後に、時計用の短い JSON と会話 JSON が同じシリアルに同時に書かれ、返事の行が壊れる
2. Whisper のあいだホストがシリアルを読まず、本体の送信が詰まる
3. echo なのに「考え中」を出すので、壊れた返事のままその画面が残る

ホストは echo なら「考え中」を飛ばし、シリアル書き込みをロックし、音声認識を別タスクにした。端末に `reply '...` が出れば返事は届いている。ChatGPT / Ollama だけ「考え中」を出し、20 秒で打ち切る。

動かしている `server.py` は古いコードのままなので、一度止めて同じコマンドで起動し直す。ファームの送信抑制はビルド済みだが、書き込みは未実施である。

```
+---------------------------+        USB         +---------------------------+
| PC                        | -----------------> | StackChan                 |
|                           |  会話 JSON 1行ずつ |                           |
|  中でやること             |  返事の2行         |  中でやること             |
|    音声を文字にする       |                    |    液晶に発話と返事       |
|    echo ならすぐ返事      | <----------------- |    マイク PCM             |
|    書き込みは同時にしない |  文字にした結果    |                           |
+---------------------------+                    +---------------------------+
```
